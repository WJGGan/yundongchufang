## 2.2 健康档案理解部分技术路径——SFT

### 任务定义

**输入**：体质测试、身体成分、视力、脊柱、足底、运动表现等结构化结果，结合年龄、目标、时间、场地形成体质画像。

**输出**：严格 Schema 的体质画像 JSON，包含六个部分——基本信息与 BMI 评价、体质五维等级（心肺耐力 / 肌肉力量 / 柔韧性 / 速度 / 爆发力，每维列出支撑体测项目原始值与判断依据）、整体评价与短板排序、健康关注点（慢病 / 用药 / 伤病史 / 脊柱 / 视力）、数据质量评估（缺失、矛盾、口语化追问）、安全评估（风险分层、能否开具处方、禁忌动作标签、强度上限）。

**功能**：理解体质画像，识别缺失、异常、矛盾的信息并向用户追问；同时产出下一阶段（处方生成）所依赖的安全约束。

### 为什么这一步要 SFT——SFT 的定位

前期用通用基模跑通链路时，暴露出的问题集中在**行为层**而非知识层：

1. **字段契约漂移**——自创维度名称、把说明文字塞进结构化字段，导致下游解析失败；
2. **输出冗长**——无关解释拉长输出甚至触发截断，是生成失败的主要根因；
3. **表达不适龄**——追问不口语化、未区分提问对象（家长 / 学生）。

因此 SFT 的目标明确为：**让模型学会"这个任务该怎么说话"——格式稳定、输出克制、表达适龄**。而知识正确性（等级分档依据、禁忌症知识）由 RAG 检索注入与代码规则兜底，不指望微调记忆知识。这一分工是整个架构的设计原则：微调治表达，检索与规则治知识。

### 训练样本构造

样本采用 messages 三段式，**与线上推理的输入完全同构**，不存在训练与推理的分布偏移：

```json
{
  "messages": [
    {"role": "system",    "content": "任务指令 + 字段语义说明 + 学段空值规则 + 安全规则 + 输出 Schema"},
    {"role": "user",      "content": "RAG 检索出的知识卡片子集（带 ID）+ 学生健康档案 JSON"},
    {"role": "assistant", "content": "专家修订后的体质画像 JSON（黄金答案）"}
  ],
  "meta": {"student_id": "...", "prompt_version": "v1.1.0", "case_tags": ["初中", "男", "超重", "哮喘"]}
}
```

训练时只对 assistant 部分计算 loss。样本格式已定稿并留有示例（`finetune/profile_sft_sample.json`）。

### 数据生产：三路来源

| 来源 | 占比（预计） | 说明 |
|---|---|---|
| **数据飞轮（主力）** | ≥ 70% | mock 档案从现有 20 份扩充到 300 份以上（按学段 × 性别 × 体能分布 × 健康标签 × 数据质量场景组合生成）→ 现有系统批量预生成画像 → **专家逐条修订** → 修订后版本即 SFT 正样本。输入输出格式与线上完全一致，是唯一真正对口的数据来源 |
| **评分表程序化样本** | 15–20% | 《国家学生体质健康标准》分年级分性别评分表为结构化数据，可程序化生成"成绩 → 等级"判定样本，覆盖全部年级 × 性别 × 单项 × 分数段，正确性由评分表保证，不消耗专家工时 |
| **防遗忘混入** | 10–20% | 从通用中文指令与医疗问答数据（如 DISC-Med-SFT）中抽样混入，防止灾难性遗忘，不作为主训数据 |

数据飞轮有一个重要副产品：**专家修订前 / 修订后的样本天然构成偏好对**，无需额外标注即可用于后续 DPO 偏好优化，与开发方案第三章的两阶段路线一致。

### 数据规模与节奏

输出结构固定的格式类任务，业界经验 500–2000 条高质量样本即可见效。计划分两步：

1. **先 300–500 条跑通训练—评测闭环**，验证指标提升方向正确（若此规模无改善，说明任务设定或数据结构有问题，盲目扩量无用）；
2. 按评测短板**定向扩充到 2000–5000 条**（开发方案约定规模），扩在错误集中的场景上，而非均匀加量。

训练集覆盖分布硬性要求：

| 维度 | 覆盖要求 |
|---|---|
| 学段 | 小学低年级 / 小学高年级 / 初中 / 高中 四段均衡 |
| 性别 | 男女接近 1 : 1（体测项目按性别不同，不可偏科） |
| 身体成分 | 消瘦 / 正常 / 超重 / 肥胖 全覆盖 |
| 健康标签 | 哮喘、血压偏高、脊柱筛查异常、伤病史、近视、无特殊 各有足量样本 |
| 数据质量场景 | 字段缺失、两表矛盾、单位混写与中文描述（免测 / 缺考）、完整干净 |
| 应拦截案例 | `can_generate_prescription=false` 的案例占比 ≥ 10%（未控高血压、运动中胸闷晕厥、急性损伤未恢复等），保证安全行为被充分训练 |

### 训练方案

- **底座**：glm-5.3 开放权重本地部署；若交付环境算力受限，可在同系列较小开放权重上以同一套数据与评测流程复训，路线不变。
- **方法**：LoRA（r = 16–64，alpha = 2r，lr 1e-4 量级，2–3 epochs），只对 response 计 loss；按验证集 loss 与结构化输出有效率双指标选取 checkpoint。
- **与 2.3 联合**：档案理解与处方生成两任务样本按约 1 : 1 混合在同一次 SFT 中训练（以 system prompt 区分任务），产出统一的 **glm-5.3-sft**，供上层 Agent 与 RAG 调用。
- **第二阶段**：用专家修订前后偏好对做 DPO，进一步压低残余的格式违规与冗长输出。

### 验收指标

评测集**独立于训练集 ≥ 200 例**（按学生与案例模板双重隔离），专家标注黄金答案。完整评测体系已定稿为可直接执行的指标模板（`finetune/体质画像微调测评指标模板.md`），硬门槛如下：

| # | 指标 | 目标 | 依据 |
|---|---|---|---|
| 1 | 结构化输出有效率（JSON 可解析、Schema 不增减、枚举与禁忌词表合法、知识引用无幻觉） | ≥ 99% | 开发方案第六节 |
| 2 | 关键计算正确率（字段抽取、BMI 计算与分类、学段空值处理、强度上限数值） | 100% | 开发方案第六节 |
| 3 | 体质画像生成准确率（五维等级、短板排序、健康关注、数据质量综合 F1） | **F1 ≥ 85%** | 需求文档指标 1 |
| 4 | 损伤风险预警准确率（risk_level 与专家分层一致） | **≥ 90%** | 需求文档指标 2 |
| 5 | 高风险与禁忌硬规则拦截率（应拦截案例全部 `can_generate_prescription=false` 并给转介建议） | 100% | 第六章安全需求 |
| 6 | 医疗边界违规（诊断 / 用药建议 / 推测疾病）与数据幻觉 | 0 | 第六章安全需求 |
| 7 | 专家盲评综合合格率（3 名以上专家，按安全 / 科学性 / 个体化 / 可执行性 / 来源一致性五维） | ≥ 90% | 开发方案第六节 |

同时与两条基线对比（未微调底座、线上 glm-5.3 直接生成），量化微调收益。

### 技术 pipeline

```
急症熔断（代码关键词匹配，不经过模型，命中即返回固定就医模板）
  → RAG 检索①（按学段与健康情况注入知识卡片，见 2.4）
  → 拼 prompt 调 LLM（glm-5.3-sft）
  → 解析 JSON
  → Pydantic Schema 校验 + 枚举 / 禁忌词表 / 知识引用合法性校验
  → 失败带错误信息重试一次
  → 仍失败则报错降级，不输出半成品
```

## 2.3 运动处方生成部分技术路径——SFT

### 任务定义

**输入**：上一阶段输出的体质画像与安全评估（短板排序、禁忌动作标签、强度上限）、学生个人条件（目标、每周可用天数、单次时长、场地、器械、偏好）、以及 RAG 检索②产出的 **30 个候选动作 + 12 张知识卡片**（见 2.4）。

**输出**：结构化运动处方 JSON——FITT-VP 处方框架、周期划分（适应期 / 提高期）、逐日周计划（每个训练日按热身 / 主训练 / 放松分块，动作以 `exercise_id` 引用并给出剂量）、强度控制（目标心率区间、RPE 范围、谈话测试）、饮食建议、风险提示与限制条款、**逐条带知识卡片引用的解释说明**。

### SFT 的训练目标：多约束同时满足

处方生成与档案理解的难点不同：它要求模型在一次生成中**同时遵守多条硬约束**——

1. 动作只能从检索给出的 30 个候选中选取，不得发明动作；
2. 训练天数与单次时长不得超出学生给的约束；
3. 不得使用命中禁忌标签的动作；
4. 强度不得超出画像给出的心率 / RPE 上限；
5. 解释只能引用上下文中实际存在的卡片 ID。

通用基模在这些约束上的典型失败是越出候选集、时长超限、引用幻觉——每次违规都会触发代码校验与重生成，直接拉长响应时间、抬高调用成本。**SFT 在这里要提升的核心工程指标是"校验一次通过率"**：把约束遵循从"靠校验兜底"变成"模型默认行为"。

### 训练样本构造

与 2.2 同构的 messages 三段式：user 为画像 + 处方请求 + 30 个候选动作 + 12 张知识卡片（与线上 prompt 完全一致），assistant 为专家修订后的处方 JSON。难例按真实使用中最容易违规的场景定向设计：

| 难例类型 | 设计意图 |
|---|---|
| 候选集受限 | 膝痛学生候选集以低冲击动作为主，训练模型"在受限积木内排期"而不越界 |
| 时间紧张 | 每周 2 天 × 30 分钟的极限约束，训练剂量压缩而非超时 |
| 器械 / 场地匮乏 | 仅家庭徒手场景，不得出现器械动作 |
| 偏好冲突 | 学生明确不喜欢的项目须替换为同效替代动作，而非强行保留 |
| 强度上限低 | 高风险 / 初学者档案，周计划整体强度不得越过画像上限 |

数据生产与 2.2 共用数据飞轮（扩充档案 → 预生成 → 专家修订），两任务在同一次 SFT 中混合训练，详见 2.2。

### 验收指标

评测集与训练集隔离原则同 2.2。处方侧硬门槛：

| # | 指标 | 目标 | 依据 |
|---|---|---|---|
| 1 | 专家盲评一致率（3 名以上运动科学专家，按科学性 / 个性化 / 安全性 / 可执行性盲评） | **> 85 分** | 需求文档指标 3 |
| 2 | 结构化输出有效率 | ≥ 99% | 开发方案第六节 |
| 3 | 动作 ID 越界率（引用候选集外或不存在的动作） | 0 | 安全需求 |
| 4 | 禁忌标签命中率（处方中出现被禁标签动作） | 0 | 安全需求 |
| 5 | 用户约束符合率（训练天数、单次时长不超约束） | 100% | — |
| 6 | 强度越限率（处方强度超出画像给定心率 / RPE 上限） | 0 | 安全需求 |
| 7 | 知识引用幻觉率（引用上下文不存在的卡片 ID） | 0 | — |
| 8 | 校验一次通过率（不触发重生成即通过全部代码校验） | ≥ 90%（并报告相对微调前基线的提升） | 工程指标 |
| 9 | 专家综合合格率 | ≥ 90% | 开发方案第六节 |

其中 3–7 项由脚本自动校验全量覆盖，1、9 项由专家抽样盲评（≥ 50 例，覆盖全部风险分层）。

### 技术 pipeline

```
安全闸门（代码：画像 can_generate_prescription=false 则停止，只给转介建议）
  → 动作候选安全硬过滤（代码：禁忌标签 / 年龄 / 器械 / 场地）
  → RAG 检索②（候选集内按短板 / 目标 / 偏好排序截断 30 动作 + 12 卡片，见 2.4）
  → 拼 prompt 调 LLM（glm-5.3-sft，流式输出）
  → 解析 JSON
  → Pydantic 校验 + 业务校验（动作 ID 存在性、是否越出候选集、是否命中禁忌标签、
     周计划完整性、训练日与时长是否超约束、解释条数与引用合法性）
  → 不通过则带问题清单重生成一次
  → 代码回填动作详情与替代方案（从动作库取，不由模型生成）
```

控制流由代码决定，不由模型决定：两次 LLM 调用之外的所有安全与一致性保障均为确定性代码。
